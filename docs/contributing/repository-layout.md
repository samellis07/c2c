# Repository layout

The pipeline runs left to right: `core` parses the `.ds` export into IR v1,
`schema` and `data` plan and move the data, `deluge` plus `shims` translate
the code, `ui` / `ui-react` generate the front end, `auth` plans access, and
`deploy` writes the Catalyst app directory. `determinism`, `quality`,
`ui-score` and `doctor` measure and gate the result.

## Packages

| path | owns |
|---|---|
| `packages/core/` | The lossless `.ds` parser (shapes A, B and C), CST → IR v1, corpus and coverage counting, feature matrix rows, canonical ordering helpers. The round-trip invariant `print(parse(src)) === src` lives here — see "Adding a construct" in [CONTRIBUTING.md](../../CONTRIBUTING.md). |
| `packages/schema/` | IR → Catalyst Data Store schema mapping: table/column types, composite parts, lookups, ZCQL limits and precision. See [docs/schema-mapping.md](../schema-mapping.md). |
| `packages/data/` | Seed generation and the data move: synthetic and CSV seeds, bulk load, files, integrity checks. |
| `packages/deluge/` | The Deluge translator: lexer/parser/AST, the builtin dispatch tables (`src/dispatch.ts`), the builtin catalogue merge (`src/catalogue.ts`), schedules, connections and fill-todos. See [deluge-builtin.md](deluge-builtin.md). |
| `packages/shims/` | The runtime shim library that translated Deluge and generated functions call (datastore, date, decimal, convert, access, errors, …). |
| `packages/ui/` | The vanilla Slate PWA target: app model and widget map (`src/model.ts`), the client runtime (`src/client-runtime.js`, `src/client/`), decorations, PWA files. See [docs/ui.md](../ui.md). |
| `packages/ui-react/` | The React UI target: the generator (`src/generate.ts`) plus the app template in `template/` (`@c2c/ui` under `template/lib/c2c-ui/`, vendored Arc under `template/lib/c2c-ui/arc/`). See [docs/react-target.md](../react-target.md). |
| `packages/ui-score/` | The UI scoring harness and corpus report. |
| `packages/auth/` | The Authentication plan: roles cloned from Creator profiles, portal users, table permissions and access policy. |
| `packages/deploy/` | Everything `c2c deploy`, `migrate-data` and `smoke` write or run: the app directory, IaC, adapters (Data Store, functions, bulk store), credentials path handling, data-centre handling, delta/cutover/rollback. See [docs/deploy-functions.md](../deploy-functions.md). |
| `packages/determinism/` | The determinism machinery: the codegen lint (`src/lint.ts`), committed manifests (`src/manifests.ts`), the corpus runner, status doc and table budget. See [determinism.md](determinism.md). |
| `packages/quality/` | Cross-app quality audits: the corpus harness, smoke inputs, prefetch read audit, no-silent-drop checks. |
| `packages/doctor/` | `c2c doctor` — read-only environment checks and evidence for the readiness gate. |
| `packages/cli/` | The `c2c` entrypoint and subcommand wiring (`parse`, `corpus`, `analyze`, `ui`, `ui-react`, `auth`, `deploy`, `migrate-data`, `doctor`, …). |

## Top level

| path | owns |
|---|---|
| `docs/` | Behaviour docs, audits and generated status files. `docs/deluge-builtins.json` and `docs/determinism-status.md` are regenerated by scripts — do not hand-edit. |
| `fixtures/redistributable/` | Committed test fixtures (openly licensed `.ds` exports, licence next to each). See "Fixtures" in [CONTRIBUTING.md](../../CONTRIBUTING.md). |
| `plugin/` | The c2c agent plugin shipped to users: skills, commands, hooks and references — a separate distributable from the converter library. |
| `scripts/` | The test runner, the test list (`test-files.txt`), the hygiene check and build helpers used by `npm test`. |
| `tests/` | Cross-package suites: `golden/`, `matrix/`, `plugin/`, `licence-gate/`, `ui-snapshots/` and the golden baseline tool. |
| `tools/` | Repo-local tools: `determinism-gate.sh`, the matrix checker, the licence, audit and security gates, and the UI checks. |

## Build and test commands

```sh
npm ci
npm ci --prefix packages/ui-react/template
npm test                       # tsc build + full node --test suite + check:hygiene
npm run check                  # npm test + tools/determinism-gate.sh
npm run check:hygiene          # scripts/check-hygiene.mjs alone
npm run determinism:update     # rewrite committed manifests (only with a reason)
npm run determinism:check      # fail on drift from committed manifests
npm run det:rebase-regen       # rebase on origin/main, drop old regens, regen last
npm run build                  # tsc only
node dist/cli/src/c2c.js ...   # the CLI against a local checkout
```

`npm test` needs no fixtures beyond the committed ones; point
`C2C_FIXTURES_DIR` at a local directory to enable the deeper local-corpus tests.

Register a test by adding its path to `scripts/test-files.txt` (one path per
line, sorted). `npm test` reads that list.
